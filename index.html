How it works

    
    
      
  • Runner: a small dbt-style runner in Python. It reads {{ ref() }} and {{ source() }} in each model to build the graph, materialises models as SQLite tables in dependency order, and indexes id columns after each build.
    • 
      
  • Tests: generic tests in models/schema.yml (unique, not_null, accepted_values, relationships, expression) plus singular SQL tests in data_tests/. Those check that GMV reconciles to the cent, that every payment lands in exactly one of the fact or quarantine tables, and that plan versions never overlap. Unit tests prove the tests catch planted errors.
    • 
      
  • Techniques: de-duplication with row_number(), type-2 slowly changing dimensions with lead(), an as-of FX join via a recursive date spine, month-over-month growth with lag(), cohort retention, and quarantine instead of silently dropping rows.
    • 
      
  • Metrics layer: metrics/metrics.yml defines each metric once; the runner compiles the SQL, so finance and dashboards use the same numbers.
    • 
    

    
The source data is synthetic, generated with realistic defects. Built with AI-assisted coding (Claude); the modelling, tests and review are my own.
